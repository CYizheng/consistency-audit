# 材料一致性核查器 · consistency-audit

同一份材料会出现在很多地方：简历、网申母版、报名表、证明材料清单、政审表。
它们之间只要有一个字段对不上——登记号差一位、毕业时间写成两个月份、
专业名用了近义词——在档案核验或政审环节就会被判为**不实填报**。

人靠记性和 grep 兜不住这件事。本工具把「哪些字段必须跨文件一致」写成一份
**口径字典**，然后机械地扫所有材料，输出一张带证据定位的冲突清单。

```
$ python audit.py -i 材料目录 -d dicts/resume.example.yaml --html
字典：resume.example.yaml  字段 13 个
抽取：3 份文件，34 个文本片段
结果：高 5 · 中 0 · 低 0
```

---

## 它到底抓什么

| 类型 | 例子 | 为什么需要单独的判据 |
|---|---|---|
| **取值冲突** | 简历写 `图书情报`，母版写 `情报学` | 归一化后仍不同即为冲突 |
| **疑似数字转置** | `2024SR1234567` 与 `2024SR1234576` | 两串**长度相同、字符组成完全相同**，普通模糊匹配只有 85% 相似度，会被 90% 阈值整批漏掉。必须用字符重排判据 |
| **高度相似** | `13800001234` 与 `1380001234` | 长度不同、相似度 95%，典型是漏字/多字，修法是补齐而不是换顺序 |
| **格式违规** | 登记号写成 `2025SR484352`（少一位） | 按字典里声明的正则校验 |
| **字段缺失** | 声明的必填字段在所有材料里都没出现 | 通常是漏页或别名没配 |

报告同时给出**字段覆盖矩阵**：哪个字段在哪份材料里压根没出现。整列为空的文件
要么确实不含这些字段，要么需要给它补别名。

## 设计上的三个决定

### 1. 为什么要有「口径字典」而不是自动推断字段

同一字段在真实材料里有很多写法：`毕业时间 / 预计毕业时间 / 毕业年月`，
`软著登记号 / 软件著作权登记号 / 登记号`。这些映射关系是**人定的**，
写下来才能复现、才能审阅、才能被下一个人接手。程序只负责按字典机械执行。

字典里每个字段可以声明的约束：

```yaml
- key: soft_copyright_id
  name: 软著登记号
  aliases: [软件著作权登记号, 软著登记号, 著作权登记号, 登记号]
  pattern: '^\d{4}SR\d{7}$'     # 归一化后必须匹配
  normalize: compact             # 去空白、全角转半角
  severity: high                 # 冲突时的报告级别
  required: true
  max_len: 40                    # 超过就别当取值（挡表头文字）
  allowed: []                    # 枚举白名单
  negatives: [签发人]            # 这些前缀后面的别名不算本字段
  note: 口径备注，会附在报告问题下面
```

### 2. 取值必须「按格式截取合法前缀」

真实材料里值后面经常粘着正文：PDF 双栏把 `310101***********1` 和
`期望待遇面议` 连成一行，母版里写成 `2024SR1234567查证官方名称后统一`。

如果只按标点截断，这些都会变成"冲突"。正确做法是：**用字段自己声明的正则
去截取合法前缀**——`^\d{17}[\dXx]` 一旦匹配成功，后面粘什么都不影响。

同理，格式要求数字而抓到的值一个数字都没有（`须与身份证一致`、`个人`、`出处`），
说明这句话在**讲**这个字段，不是在**填**它，直接丢弃。

### 3. 「材料」和「关于材料的笔记」必须分开

材料库里混着大量说明文档、版本说明、问答稿，它们本来就会并列写出
「4325 还是 4352」这种讨论。把这些算成冲突是**范畴错误**。

所以工具只核查**要投出去的那几份**，其余用 `--exclude` 排除：

```bash
python audit.py -i 网申字段母版.md 简历 报名表 证件与学历 \
    -x "版本说明*" "_backup*" "*说明*.md" \
    -d dicts/resume.example.yaml --html
```

## 在真实材料上把噪声压下去的过程

自测数据是干净的，真实材料不是。这个工具的精度是靠一轮轮在真实语料上
看误报、改判据换来的，过程如实记录：

| 轮次 | 问题数 | 当轮暴露的误报 | 对应的判据修正 |
|---|---|---|---|
| v1（整库扫） | **16** | `**`、反引号、`（见§三）` 被当成字段值 | 值截断字符集加入 Markdown 修饰符 |
| v2（缩小作用域 + `--exclude`） | 10 | 表格里字段名与值分列，抓不到 | 新增表格「表头→右邻格」配对 |
| v3 | 8 | 「出生年月须与身份证一致」整句被当值 | 别名右侧必须紧跟分隔符 |
| v4 | 2 | `310101***********1期望待遇面议`、`2024SR1234567查证…` | 按声明格式截取合法前缀 |
| v5 | 1 | 表头行 `姓名｜关系｜工作单位` | `max_len` + `allowed` 白名单 |
| v6 | **0** | `校（院）长姓名 陈立言`（学历备案表的签发人） | `negatives` 负例前缀 |

从 16 条噪声降到 0 条，靠的不是放宽阈值，而是**每一条误报都对应一条可解释的判据**。
放宽阈值只会让真问题一起消失。

## 已知边界（不是待办，是设计取舍）

1. **纯版式位置不识别**。简历顶部的姓名是一个标题行，没有 `姓名：` 这样的标签，
   工具抓不到。覆盖矩阵里那一列会是空的——这是「没有标签」而不是「缺字段」。
2. **证件类 PDF 的双栏排版**会把相邻信息挤到同一行。签发人姓名、条形码数字
   可能被误认为字段值。用 `negatives` 或把证件类排除出姓名核查范围。
3. **不做校验位推算**。身份证号、统一社会信用代码的校验位不会被工具修正——
   改还是不改，得人决定。工具只负责指出「这里和别处不一样」。
4. **不追求召回全部字段**。字典里没声明的字段不会被核查。宁可少抓，
   也不要给出无法解释的报警。

## 安装与使用

只需标准库之外的四个轻量包，无模型、无 GPU、无网络：

```bash
pip install -r requirements.txt
python tools/build_samples.py     # 生成虚构演示材料
python audit.py --self-test       # 自检：应全部通过
python audit.py -i samples --html # 跑演示，看报告长什么样
```

报告有三种形态：Markdown（默认，适合进 Git）、`--html`（适合看）、
`--json`（适合接自动化）。

**退出码**：`0` 无高优先级问题 · `1` 存在高优先级问题 · `2` 参数/数据错误。
可以直接接在提交前钩子里，让「材料改完就核一遍」变成不需要记性的事。

```
caudit/
  extract.py          docx / pdf / md / txt → 带定位的文本片段
  dictionary.py       口径字典加载、别名匹配、取值截断
  normalize.py        值归一化（无损变换）
  detect.py           冲突 / 笔误 / 格式 / 缺失 四类检测
  report.py           Markdown / HTML / JSON 渲染
dicts/
  resume.example.yaml 示例口径字典（求职材料，13 个字段）
samples/              虚构演示材料（林小舟，含故意埋的 4 处冲突）
tools/build_samples.py  演示材料生成器（可复现）
```
