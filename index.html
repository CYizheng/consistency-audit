CLI · 纯标准库之外仅 4 个轻量依赖 · 无模型

材料一致性核查器

同一份材料散落在简历、网申母版、报名表和证明材料里。只要有一个字段对不上—— 登记号差一位、毕业时间写成两个月份、专业名用了近义词——档案核验时就会被判为不实填报。 人靠记性兜不住，这个工具把它变成一次可复现的扫描。

它抓什么

取值冲突
简历写 图书情报，母版写 情报学——归一化后仍不同即报
数字转置
2024SR1234567 与 2024SR1234576：长度相同、字符组成完全相同，只是顺序不同
高度相似
13800001234 与 1380001234：长度不同、相似度 95%，是漏字而非转置
格式违规
登记号少一位、手机号 10 位——按字典里声明的正则校验
字段缺失
声明的必填字段在所有材料里都没出现，通常是漏页或别名没配

为什么转置要单独判

0484352 与 0484325 的模糊相似度只有 85%。 用常见的 90% 阈值做近似匹配，这类错误会被整批漏掉； 而把阈值放宽到 80%，两个真实不同的编号又会互相误报。 所以这里换判据：等长且字符频次完全相同才算转置——精度和召回同时拿到。 

# 不是相似度，是字符重排
sorted("2024SR1234567") == sorted("2024SR1234576")   → True
len(a) == len(b)                                    → True

精度是在真实材料上磨出来的

自测数据是干净的，真实材料不是。每一轮误报都对应一条可解释的判据修正，而不是放宽阈值：

16
v1 整库扫
10
v2 缩小作用域
8
v3 分离符判据
2
v4 前缀截取
1
v5 白名单
0
v6 负例前缀

30 份真实材料、13 个口径字段。放宽阈值只会让真问题一起消失，所以每一条误报都改判据。

怎么用

pip install -r requirements.txt
python audit.py -i 网申母版.md 简历 报名表 -x "版本说明*" --html

退出码 0 无高优先级问题、1 存在高优先级问题、2 参数错误， 可以直接接进提交前钩子——让「材料改完就核一遍」变成不需要记性的事。
